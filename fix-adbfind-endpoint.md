# Отложенная задача: `adbfind` не публикует `adb-connect-port`

Статус: **отложено**, в план `dsu` не входит (решение пользователя). Записано 2026-11-10.

## Симптом (проверено)
- `adb devices` показывает `127.0.0.1:40927 device`, `adb -s 127.0.0.1:40927 shell id` даёт `uid=2000(shell)`, `context=u:r:shell:s0`.
- При этом файлов `$PREFIX/tmp/adb-connect-port` и `$PREFIX/tmp/adb-pair-port` нет.
- `gsh status` печатает `connect endpoint: none`, `adb: not connected (run: gsh pair CODE)` — хотя ADB подключён.
- `$PREFIX/tmp/god-mods.log` содержит `builtin adbfind ok`: мод загружен.

## Что известно по коду (`app/src/main/java/adbfind/AdbFind.java`)
- Порты ищутся через `NsdManager.discoverServices` для `_adb-tls-connect._tcp` и `_adb-tls-pairing._tcp`, затем `resolveService` по одному (`pump()`), результат пишется в `$PREFIX/tmp/<file>`.
- Файл пишется только после успешного `onServiceResolved`. При `onResolveFailed` повтор только для кода 3 (`FAILURE_ALREADY_ACTIVE`).
- `onServiceLost` удаляет файл.
- `gsh` читает адрес только из `adb-connect-port` и ничего не знает о подключениях, сделанных вручную.

## Гипотезы (не проверены)
1. NSD не находит сервис (нет Wi‑Fi или сети, отладка включена в режиме без mDNS, ограничение HyperOS).
2. `resolveService` падает с кодом, отличным от 3, и повтора нет.
3. Файл создан и сразу удалён через `onServiceLost` (отладку выключали/включали, сеть пропала).
4. Подключение выполнено вручную (`adb connect 127.0.0.1:40927`), без участия NSD, поэтому файла и нет.
5. Права или `TMPDIR`: проверить, что `tmp` в моде = `$PREFIX/tmp` (`files/usr/tmp`).

## Проверки, когда дойдёт очередь
- `logcat -s AdbFind` (теги `discovering ...`, `start failed ...`, `adb-connect-port = ...`) при включении/выключении «Беспроводной отладки».
- Есть ли Wi‑Fi в момент включения отладки; поведение при включённой точке доступа.
- Создаётся ли файл при включении отладки с нуля и при смене порта.

## Возможные исправления
- `gsh`/`dsu`: если файла нет, брать подключённое устройство из `adb devices` (запасной путь).
- `adbfind`: логировать коды `onResolveFailed`, повторять при любых временных ошибках, при старте публиковать уже подключённое устройство.
- Статус в `AdbScreen` показывать по `adb devices`, а не только по файлу.

Влияние на `dsu`: этапы 1–2 плана работают через `adb devices`/`rish` и от этого дефекта не зависят, но автоподбор порта (этап 3) зависит.

## Обновление 2026-11-11 (наблюдение при шаге 0 этапа 4а)
- Файл `$PREFIX/tmp/adb-connect-port` **появился**: `10.14.238.211:40927` (создан 02:33:41, у устройства теперь есть сетевой адрес). Подключённое устройство в `adb devices` по-прежнему `127.0.0.1:40927` (тот же порт).
- Это подтверждает гипотезу 1: раньше `adbfind` не публиковал порт, пока у телефона не было Wi‑Fi/сети. Дефект, вероятно, не в коде, а в условиях (без сети NSD ничего не находит). Остаётся проверить: появляется ли файл при включённой отладке без сети.

## Обновление 2026-11-11 (после перезапуска Termux)
- Телефон переключается между двумя сетями (в `adb-connect-port` встречались `192.168.0.3`, `192.168.0.233` и `10.14.238.211`). При смене сети Android сам выключает Беспроводную отладку; файл порта при этом может остаться со старым адресом, пока `adbfind` не получит `onServiceLost`/новый сервис. `dsu` теперь не полагается на файл: после включения отладки через мод он удаляет файл и ждёт свежую запись (до 20 с).
