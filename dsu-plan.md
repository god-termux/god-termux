# План: команда `dsu` — shell от Android `shell` (uid 2000) через ADB/Shizuku, аналог `tsu` без root

Версия 2 (2026-11-10): учтены решения пользователя и отчёт этапа 0 (`dsu-reports/00-razvedka.md`). Документ — план, не код.

Пометки:
- **(проверено)** — видел в коде/на устройстве, либо подтверждено отчётом этапа 0;
- **(допущение)** — общее знание об Android/ADB, на устройстве не проверялось; входит в план проверки (раздел 8).

Проверенные факты, на которые опирается план (в дополнение к `context.md`):
- Лицензия `tsu` — ISC (`$PREFIX/share/doc/tsu/LICENSE`, © 2020 Cswl Coldwind). Заимствовать можно, сохранив уведомление.
- `/data/local/tmp`: `drwxrwx--x shell shell`, `shell_data_file:s0`; из Termux `ls` → `Permission denied`. Писать/читать туда может только процесс shell (`adb push`, `adb shell 'cat > …'`, `rish -c`). `mkdir` от shell создаёт каталоги `777` (отчёт 0).
- `GodRuntime.copyTree` копирует любой файл из `assets/god/**` в `$PREFIX`, сравнивая sha256, ставит exec-бит. Для поставки достаточно `assets/god/bin/dsu` — но только при пересборке APK.
- `build-local.sh`, строка 67: `cp god/runtime/dapt god/runtime/gsh god/runtime/wlrun god/runtime/xfce-wl $A/bin/`.
- `rish` — `#!/system/bin/sh`-скрипт над `app_process … ShizukuShellLoader "$@"`; аргументы прокидываются как есть.
- `adb` 1.0.41 / 37.0.0p1 установлен. Сейчас подключено `127.0.0.1:40927 device` (вручную). Shizuku мёртв (`Request timeout`).
- `gsh` существует в трёх идентичных копиях: `god/runtime/gsh`, `$PREFIX/bin/gsh`, `~/.local/bin/gsh`; первым в `PATH` идёт `$PREFIX/bin`. Внешних скриптов, вызывающих `gsh`, нет (`desk`, `chromen`, `go`, `~/.local/bin/*` — не вызывают; упоминания только в `god/README.md`, `build-local.sh`, `~/.termux/mods.bak/adbfind/mod.json`).
- Через `adb shell` на удалённую сторону передаётся только `TERM`; `LD_PRELOAD`, `PREFIX`, `TERMUX_*`, `LANG` — нет. Удалённые значения: `HOME=/`, `TMPDIR=/data/local/tmp`, системный `PATH` (отчёт 0).
- `printf '%q '` из bash понимается удалённым mksh побайтно (пробелы, кавычки, `$'x\ny'`, юникод, `*`, `;id`, пустая строка). Коды возврата и stdin проходят через `adb shell` (отчёт 0).
- Login-оболочка `adb shell` **не** читает `$ENV`; rc подхватывается только при явном `ENV=… sh -i` (отчёт 0).
- PTY, `TERM` и начальный размер окна доходят; смена размера — при `SIGWINCH` клиенту `adb` (на реальном окне Termux не проверено). `Ctrl+C` → код 130, сессия жива (отчёт 0).
- **Дефект вне плана**: `adbfind` сейчас не публикует `$PREFIX/tmp/adb-connect-port`, хотя ADB подключён (`dsu-reports/fix-adbfind-endpoint.md`). Следствие для `dsu`: нужен запасной поиск устройства через `adb devices`.

## 1. Выбор архитектуры

### Честная оценка цели
Цель «сессия от adb со **всеми путями Termux**» в полном виде **недостижима без root** (раздел 3, 11б `context.md`; подтверждено отчётом 0: `bash` Termux → `inaccessible or not found`, `ls /data/data/com.termux/files` → `Permission denied`). Файлы `$PREFIX` — `0700`, uid `u0_a318`, метка `app_data_file` с категориями приложения; домен `shell` их не читает и не исполняет. Это запрет SELinux + DAC, не обходится переменными, `chmod`, shim'ами.

**Решение пользователя**: `dsu` без программ Termux как *основная* среда не принимается → основной сценарий — **вариант E**: терминал остаётся обычным Termux, а привилегированные системные команды вызываются обёртками. `dsu` получает **две роли**:
1. **Основная — исполнитель команд от shell** (`dsu -c`, `dsu CMD…`) и набор обёрток `g*` (`gpm`, `gam`, `gset`, `gcmd`, `gdumpsys`, `gwm`, `gappops`), вызываемых прямо из Termux. Пользователь остаётся в своей среде со всеми программами Termux.
2. **Вторая — отдельная shell-сессия** для системных утилит (исследование системы, `top`, `logcat`, `vi` toybox). В приглашении и `dsu -h` явно: «программ Termux здесь нет».

Что **достижимо**: полноценная интерактивная сессия uid 2000 внутри вкладки Termux (PTY, `TERM`, размер окна, `Ctrl+C` — проверено); «среда Termux» на уровне окружения (`TERM`, `LANG`, `PS1`, своя `HOME`/`TMPDIR` в `/data/local/tmp/dsu/`, алиасы, rc-файл, подсказки при попытке запустить `python`/`git`/`vim`); режим одной команды с кавычками, stdin и кодом возврата (проверено); диагностика и сопряжение на базе `adbfind`. **Отложено как эксперимент (этап 4)**: «обратный мост» `tx CMD` — выполнить команду **в Termux** из сессии shell через локальный TCP (у `shell` группа `inet` — проверено; у Termux `INTERNET`).

### Сравнение вариантов A–E
| Вариант | Оценка |
|---|---|
| **A. Скрипт** `dsu` (bash, по образцу `tsu`) поверх `adb`/`rish` | **Ядро реализации.** Без пересборки APK, ставится вручную сразу, затем через `GodRuntime`. Все компоненты уже на устройстве. |
| **B. Скрипт + доработка `adbfind`** | **Отложен (решение пользователя)** вместе с дефектом `adb-connect-port`. Пока `dsu` компенсирует запасным путём через `adb devices`. |
| **C. ADB-клиент на Java** | **Отвергнут.** Криптозависимости (SPAKE2), сборка без NDK, высокая цена ошибок, выигрыш — только отказ от уже установленного `adb`. |
| **D. Копия утилит Termux в `/data/local/tmp`** | **Отвергнут как общий путь.** `DT_RUNPATH=/data/data/com.termux/files/usr/lib` (проверено), абсолютные пути в скриптах/конфигах, 11 ГБ, расхождение версий при `pkg upgrade`. Точечные **статические** утилиты — эксперимент этапа 4в. |
| **E. Termux-терминал + обёртки** | **Основной сценарий** (решение пользователя), реализуется внутри A: `dsu -c`, `dsu CMD…`, обёртки `g*` через `dsu --install-wrappers`. |

**Итог: A с приоритетом E (этап 1) → интерактив (этап 2) → B отложен (этап 3) → эксперименты (этап 4) ; C и D не делаем.**

### `gsh`
`dsu` поглощает логику `gsh` (выбор канала `rish` → ADB, `status`, `pair`). `gsh` остаётся **рабочей тонкой обёрткой**: `gsh status` → `dsu status`, `gsh pair X` → `dsu pair X`, `gsh -c '…'` → `dsu -c '…'`, `gsh cmd…` → `dsu -c "$*"` (сохранить старую склейку `"$*"` ради совместимости, но в `--dbg` предупреждать). Проверка вызывающих выполнена (см. факты выше): менять безопасно; обновить все **три** копии (`god/runtime/gsh`, `$PREFIX/bin/gsh`, `~/.local/bin/gsh`) или удалить `~/.local/bin/gsh` как дубликат (решает исполнитель, отразить в отчёте).

## 2. Что переиспользовать из `adbfind`

Нумерация методов — по разделу 5.2 `context.md`.

### Используется как есть (без правок Java)
- `start`/`pump` — NSD-обнаружение и файлы-контракты `$PREFIX/tmp/adb-connect-port`, `adb-pair-port`. `dsu` читает их при каждом вызове, **но** из-за дефекта (файл не публикуется при живом подключении) порядок поиска endpoint в `dsu`:
  1. `--ep HOST:PORT` / `DSU_EP` (при необходимости `adb connect`);
  2. иначе `adb devices` → единственное устройство в состоянии `device` (несколько → ошибка 125 «укажите `--ep`»);
  3. иначе `$PREFIX/tmp/adb-connect-port` → `adb connect`, `get-state`;
  4. иначе «нет канала».
  (Реализовано в этапе 1 именно в таком порядке — `adb devices` раньше файла, потому что отражает фактическое подключение; принято.) Кэш `dsu-last-ep` не нужен: `adb devices` дёшев.
- `notifyPair` + `RemoteInput` + `BroadcastReceiver adbfind.PAIR` — ввод кода из уведомления. `dsu pair КОД` — альтернатива из терминала (`adb pair <pairEp> КОД`; при отсутствии `adb-pair-port` — принимать `--pair-ep HOST:PORT` вручную, т.к. NSD ненадёжен).
- `doPair`/`doConnect`/`doTest`/`doStatus`, `AdbScreen`, `hookSettings`, `publishShortcut`, `pinShortcut`, `uiIntent` — не трогаем.

### Что менять в `adbfind` — **этап 3, отложен**
1. `doConnect()` → публиковать `$PREFIX/tmp/adb-state`.
2. Автоподключение при смене `connectEp` в `pump()`.
3. При старте мода публиковать уже подключённое устройство (`adb devices`) — закрывает дефект `adb-connect-port`.
4. Логировать коды `onResolveFailed`, повторять при временных ошибках.
5. Кнопка «Открыть привилегированный терминал» в `AdbScreen` (запуск сессии Termux с `$PREFIX/bin/dsu` через `RUN_COMMAND` — **(допущение)** приложение должно иметь своё разрешение `com.termux.permission.RUN_COMMAND` в `uses-permission`, проверить).
6. Строка в `AdbScreen`: «Команда в терминале: `dsu`».

Правки — в **обе** копии (`app/src/main/java/adbfind/`, `~/mods-src/adbfind/`, предварительно `diff -r`). Обкатка без пересборки — внешним модом под другим именем (например `dsufind`), при этом встроенный `adbfind` отключить через `~/.termux/builtin-mods.disabled` (внешний мод с именем встроенного игнорируется — `ModLoader.isBuiltinName`, проверено; два NSD-обнаружителя писали бы одни файлы).

### Новое, вне `adbfind`
- `god/runtime/dsu` — вся логика (bash). rc-файл для удалённого mksh — heredoc внутри `dsu` (один файл для `GodRuntime`), заливается в `/data/local/tmp/dsu/rc.sh`.
- Обновлённый `god/runtime/gsh` — обёртка.
- Обёртки `g*` генерируются `dsu --install-wrappers` в `$PREFIX/bin` (не хранятся в репозитории как отдельные файлы).

## 3. Спецификация команды `dsu`

### Синтаксис
```
dsu -c 'строка'                      # выполнить строку как есть на удалённой стороне (совместимость с gsh -c)
dsu [ОПЦИИ] [--] КОМАНДА [АРГ…]      # выполнить команду (режим sudo); аргументы экранируются
dsu [ОПЦИИ]                          # интерактивный shell от uid 2000 (этап 2)
dsu status | pair КОД | push ФАЙЛ… | --install-wrappers | --settings | -h | --version
```

### Флаги
| Флаг | Смысл | Этап |
|---|---|---|
| `-c СТРОКА` | «сырой» режим: строка передаётся как есть (`sh -c` на удалённой стороне). | 1 |
| `--rish` / `--adb` | принудительный канал. По умолчанию `rish`, при неудаче `adb` (решение пользователя). | 1 |
| `--ep HOST:PORT` | явный endpoint ADB (обход дефекта `adb-connect-port` и выбор при нескольких устройствах). | 1 |
| `-t` | принудительный PTY для одной команды (`adb shell -t`; нужно для `top`, `less`, `vi`). | 1 |
| `--dbg` | отладка (`_DSU_DEBUG=1`, `log_DEBUG` как в `tsu`): выбранный канал, endpoint, собранная командная строка. | 1 |
| `-s SHELL` | удалённая оболочка: `/system/bin/sh` (по умолчанию), `/system/bin/mksh`, `toybox sh`. Пути в `$PREFIX` отвергаются с пояснением. | 2 |
| `-p` / `-a` | системные пути в начало/конец `PATH` относительно `/data/local/tmp/dsu/bin` (личные sh-скрипты пользователя). По умолчанию `-p`. | 2 |
| `-E` | передать подмножество окружения: `LANG`, `LC_*`, `COLORTERM`, `TZ`, `EDITOR` (если системный), `DSU_*`. Без `-E` — только `TERM` (его передаёт сам `adb`) и `LANG`. **Никогда**: `LD_PRELOAD`, `LD_LIBRARY_PATH`, `PREFIX`, `HOME`, `TMPDIR`, `PATH`, `TERMUX_*`, `SHELL`. | 2 |
| `-h`, `--version` | справка (с явной фразой «программ Termux в сессии shell нет; используйте обёртки g*»), версия. | 1 |

Флаги важнее файла `~/.termux/dsu.conf` (решение пользователя). Формат файла — `KEY=VALUE`, читается через `source` только если файл принадлежит пользователю; ключи: `DSU_CHANNEL=rish|adb`, `DSU_EP`, `DSU_SHELL`, `DSU_PATH_ORDER=p|a`, `DSU_RC_EXTRA` (путь к локальному файлу, дописываемому в удалённый rc).

### Подкоманды
- `dsu status` — канал `rish` (с таймаутом 3 с), endpoint из файла / `adb devices`, `get-state`, uid удалённой стороны, наличие `adb`, версия `dsu`, последняя ошибка (`$PREFIX/tmp/dsu-last-error`). Не вешаться при мёртвом Shizuku.
- `dsu pair КОД [--pair-ep HOST:PORT]` — `adb pair`, затем `adb connect`; проверка «6 цифр».
- `dsu push ФАЙЛ…` — скопировать в `/data/local/tmp/dsu/bin/` (`adb push` либо `rish -c 'cat > …'`), `chmod 755`. ELF из `$PREFIX` — предупреждение (вариант D). Этап 2.
- `dsu --install-wrappers` — создать в `$PREFIX/bin` обёртки (решение пользователя: с префиксом `g`, только по явному запросу):

  | Обёртка | Удалённая команда |
  |---|---|
  | `gpm` | `pm` |
  | `gam` | `am` |

Перед созданием — `command -v gpm` и т.п.: если имя уже занято **не нашей** обёрткой (проверка по маркерной строке `# dsu-wrapper`), не затирать, сообщить. `dsu --remove-wrappers` — удалить только файлы с маркером. ### Перенос кавычек, stdin и кодов возврата (основной сценарий, этап 1)
- `dsu CMD ARG…` и обёртки: локально `cmd=$(printf '%q ' "$@")`, удалённо `sh -c "$cmd"` — **проверено** побайтно для пробелов, кавычек, `$'…'`, юникода, `*`, `;id`, пустых строк. Запасной путь через `base64` не нужен.
- `dsu -c СТРОКА` — без экранирования (как `gsh -c`); документировать.
- stdin: без `-t` поток stdin идёт удалённой команде (`echo hi | dsu cat` — проверено на adb). С `-t` stdin — терминал. Для `rish` — проверить (раздел 8, п. 2/8).
- Коды возврата: `adb shell` возвращает удалённый код (проверено: `false`→1, `exit 7`→7, не найдено→127). Для `rish -c` — проверить. Собственные коды `dsu`: `125` — нет канала; `126` — команда есть в `$PREFIX/bin`, но недоступна shell (локальная подсказка); `127` — не найдена ни локально, ни удалённо (удалённый 127 пробрасывается как есть). Обёртки возвращают код `dsu` без изменений.
- Поведение при недоступном канале (обёртки и `dsu -c`): одно сообщение в stderr, код 125, **без** зависания: `timeout 3 rish -c true`, `timeout 5 adb connect`, `timeout 5 adb -s EP get-state`. Текст — из таблицы раздела 6. Кэш выбранного канала `$PREFIX/tmp/dsu-channel` на 30 с, чтобы серия `gpm …` не проверяла канал каждый раз (сброс при ошибке).

### Окружение на удалённой стороне
Передаётся только `TERM` (проверено) → `dsu` строит `env -i` явно:
- режим команды: `env -i PATH=<система>:/data/local/tmp/dsu/bin HOME=/data/local/tmp/dsu/home TMPDIR=/data/local/tmp/dsu/tmp TERM=$TERM LANG=$LANG [-E-переменные] sh -c "$cmd"`. Системный `PATH` берётся **удалённый** (отчёт 0: `/product/bin:/apex/…:/system/bin:/system/xbin:/odm/bin:/vendor/bin:/vendor/xbin`) — не хардкодить; получить один раз `dsu -c 'echo $PATH'` и кэшировать в `$PREFIX/tmp/dsu-remote-path`, либо не трогать `PATH` вовсе в режиме команды (проще; рекомендуется для этапа 1), а менять его только в интерактиве.
- интерактив (этап 2): то же + `ENV=/data/local/tmp/dsu/rc.sh` и **явный `sh -i`** (login-оболочка `$ENV` не читает — проверено). `PS1` в rc: `dsu:shell@<hostname>:<pwd> $` + первая строка при входе: «shell uid 2000. Программ Termux здесь нет — для них обычная вкладка; системные команды из Termux: gpm, gam, gset, gcmd, gdumpsys, gwm, gappops».
- `ANDROID_ROOT`, `ANDROID_DATA` — сохранять удалённые значения (`/system`, `/data` — проверено) внутри `env -i`.
- `LD_PRELOAD`/`LD_LIBRARY_PATH` — локально перед `rish`: `env -u LD_PRELOAD -u LD_LIBRARY_PATH rish …` (для `adb` не требуется — Termux-процесс, работает с шимом; но безвредно сделать то же). Пересылает ли `rish` `System.getenv()` — **(допущение; проверить `rish -c env`)**.

### Подсказки (локально, **после** удалённого кода 127)
Изменено по итогам этапа 1: в `$PREFIX/bin` у Termux есть собственные `am`, `pm`, `settings`, `cmd`, `logcat`, поэтому проверка «до обращения к каналу» давала бы ложный 126 для `gam`/`gpm`. Теперь: если удалённая сторона вернула 127 и `command -v КОМАНДА` указывает в `$PREFIX/` — сообщение «`python` — программа Termux; процесс shell (uid 2000) не имеет доступа к `/data/data/com.termux`. Запустите её в обычной вкладке Termux. Системные аналоги: ls/grep/sed/awk/tar/ps/top/vi → toybox», код 126. Иначе 127 как есть. Цена — один лишний удалённый вызов в редком случае ошибки; принято.

Имена обёрток: `g<команда>`, исключение `settings → gset` (имя `gsettings` занято glib); произвольное имя — синтаксис `КОМАНДА:ОБЁРТКА` в `--install-wrappers`.

### Порядок каналов
`rish` (если `RISH_APPLICATION_ID=com.termux timeout 3 rish -c true` успешен) → ADB (endpoint по порядку из раздела 2). Флаги `--rish`/`--adb` принудительно; `DSU_CHANNEL` в `dsu.conf`.

## 4. Устройство терминальной сессии (этап 2)

- **PTY со стороны Termux** — вкладка Termux (`JNI.createSubprocess`). Свой терминал не нужен.
- **PTY со стороны shell**: `adb -s EP shell` при tty-stdin → shell v2, PTY у adbd, `TERM` клиента (проверено: `tty`=`/dev/pts/N`, `TERM=xterm-256color`, размер 31×97). Для `rish` — **(допущение)**, проверить `rish -c tty` и интерактивный `rish`.
- **Размер окна**: доходит при `SIGWINCH` клиенту `adb` (проверено через pty из Python; **на реальном окне Termux проверить поворотом экрана/сменой клавиатуры → `stty size`**). Без локального tty `adb shell -tt` даёт PTY с размером `0 0` — для `-t` в режиме команды это норма, документировать. `rish` — проверить.
- **Сигналы**: `Ctrl+C` → удалённый код 130, сессия жива (проверено). `Ctrl+D` закрывает. `Ctrl+Z` — проверить (может приостановить локальный `adb`); `top`/`logcat` под `Ctrl+C` — проверить.
- **Запуск (как реализовано в этапе 2)**: `adb -s EP shell -t "mkdir -p …; <синхронизация rc по sha256: если первая строка `# dsu-rc sha256=…` не совпала — echo BASE64 | base64 -d > rc.sh>; test -x SHELL; cd CWD; HOME=… TMPDIR=… TERM=… [LANG, -E] ENV=/data/local/tmp/dsu/rc.sh DSU_BIN=… DSU_PATH_ORDER=… exec SHELL -i"`. **Без `env -i`** (он стёр бы системный `PATH`/`ANDROID_*`; удалённая среда и так создаётся заново adbd). rc заливается base64 в той же строке (один round-trip, одинаково для adb и rish), а не `adb push`. **Интерактив по умолчанию через adb** (PTY проверен); `rish` — только `--rish` или при отсутствии adb, с предупреждением «не проверено» — пересмотреть после проверки 22. `-s` принимает только одно слово-путь (`/system/bin/sh`, `/system/bin/mksh`); `toybox sh` не поддерживается — достаточно.
- **Рабочая папка**: `cd $HOME` (`/data/local/tmp/dsu/home`). Если локальный `$PWD` в `/sdcard` или `/storage/emulated/0` — перейти туда же (у shell `sdcard_rw` — проверено по группам). `$PWD` внутри Termux — пропустить, подсказка в `--dbg`.
- **Первый запуск / обновление rc**: `dsu` удалённо `test -f rc.sh && head -1 rc.sh` (в первой строке — sha256 содержимого); при несовпадении — `mkdir -p /data/local/tmp/dsu/{home,tmp,bin}` и заливка через `adb push` временного файла (или `rish -c 'cat > …'`). Из Termux каталог не читается — проверять только удалённо. Права каталогов (`chmod 700`, `umask 077`) — **необязательное улучшение, низкий приоритет** (решение пользователя); если делать — одна строка `chmod 700` после `mkdir`.

## 5. Поставка и установка

1. **Исходник**: `god/runtime/dsu` (bash, shebang `#!/data/data/com.termux/files/usr/bin/bash`), обновлённый `god/runtime/gsh`. Шапка: `Derived from tsu (c) 2020 Cswl Coldwind, ISC`.
2. **Сразу, без пересборки**: `cp god/runtime/dsu $PREFIX/bin/ && chmod 700 $PREFIX/bin/dsu`; `gsh` — во все три копии (сделано в этапе 1). Пока `bin/dsu` нет в assets установленного APK, `GodRuntime` файл не трогает (проверено по коду) — ручная копия не затирается.
   **Находка этапа 1**: `$PREFIX/bin/gsh` **есть** в assets установленного APK, поэтому `GodRuntime` при каждом старте Termux возвращает старую версию `gsh` (sha отличается). Старый `gsh` работоспособен (rish → adb через файл порта, без запасного пути `adb devices`); новая версия приедет после пересборки APK. Обходных путей без пересборки нет (кроме переноса `~/.local/bin` вперёд в `PATH`, что не рекомендуется). Принято как известное ограничение; документировано в `CLAUDE.md`.
3. **В APK (к следующей плановой пересборке)**: добавить `god/runtime/dsu` в `cp …` на строке 67 `build-local.sh`. После этого ручные правки `$PREFIX/bin/dsu` затираются при каждом старте — править только исходник.
4. `modbuild` не нужен (не Java-мод).
5. **Документация**: `god/README.md` и `CLAUDE.md` — `dsu` основная команда, `gsh` «для совместимости», список `g*`-обёрток; `~/.termux/mods.bak/adbfind/mod.json` не трогать (бэкап).
6. **Обновление**: `dsu --version`; удалённый rc переливается по хэшу; `/data/local/tmp/dsu/` пересоздаётся при отсутствии **(допущение: система может чистить `/data/local/tmp` при перезагрузке)**.

## 7. Безопасность

По решению пользователя безопасность самого `dsu` — **не приоритет**; требований к `dsu` не выставляется. Для сведения (без обязательств): пользователь получает uid 2000 (не root): установка/удаление приложений, `pm grant`, `settings`, `input`, `screencap`, `logcat`, внешнее хранилище; ключ `~/.android/adbkey` эквивалентен доступу к shell; каталоги в `/data/local/tmp/dsu/` создаются `777` (исполнитель вручную закрыл до 700/600; в `dsu` — необязательно). Лицензия `tsu` — ISC, уведомление сохранять.

### Спецификация безопасности `tx` («обратный мост» shell → Termux, этап 4б) — **обязательна**
Причина: `tx` открывает выполнение произвольных команд в Termux (uid приложения, со всеми данными пользователя) любому процессу, который дотянется до сокета. Требования:
1. **Отключён по умолчанию.** Слушатель запускается только флагом `dsu --tx` (или `DSU_TX=1` в `dsu.conf`) и живёт как **дочерний процесс `dsu`** — завершается вместе с сессией (`trap EXIT`), не демон.
2. **Только `127.0.0.1`**, случайный свободный порт; никогда `0.0.0.0`.
3. **Токен**: 32+ случайных байт (`head -c 32 /dev/urandom | base64`), генерируется на каждую сессию, передаётся на удалённую сторону **только** через `env -i … DSU_TX_PORT=… DSU_TX_TOKEN=…` в командную строку `adb shell` (в `/data/local/tmp` не писать: читаем другим процессам shell — а их может породить любое приложение с ADB-доступом). Сервер отвергает запросы без токена, сравнение — полным совпадением.
4. **Протокол**: одна команда на соединение; первая строка — токен, далее `argv` в NUL-разделённом виде (без интерпретации shell'ом на стороне Termux; выполнение `exec -- "${argv[@]}"`), stdin/stdout/stderr стримятся, код возврата — последней строкой/отдельным каналом. Никаких `eval`.
5. **Журнал**: `$PREFIX/tmp/dsu-tx.log` — время, порт, первые 200 байт команды, код возврата, отказы по токену. Ротация не нужна (сессионный).
6. **Ограничение по времени**: соединение без токена в течение 2 с закрывается; слушатель — не более N (например 4) одновременных команд.
7. **Реализация**: `socat`/`nc` из Termux **не подходят** для аутентификации — нужен маленький сервер (bash + `nc -l` недостаточно; варианты: Python из Termux, либо `socat … EXEC:` с обёрткой, проверяющей токен). Выбор — за исполнителем в отчёте этапа 4б с обоснованием; зависимость должна уже стоять на устройстве.
8. **Удалённая сторона**: `tx` — sh-скрипт в `/data/local/tmp/dsu/bin/tx`, использующий `toybox nc` **(допущение: `nc` есть в toybox 0.8.12-android; проверить `toybox nc`)**.
9. Критерий «готово» (безопасность): соединение без токена/с неверным токеном → отказ и строка в журнале; после выхода из `dsu` порт закрыт (`ss -ltn`/`netstat`); слушатель не стартует без флага.
