## 3. Что не проверено и почему
- Показывает ли HyperOS системный диалог/уведомление при программном включении (экран не наблюдал).
- Поведение без сети вообще (нет Wi‑Fi): `adbfind` без сетевого адреса, ожидается тайм-аут 20 с и сообщение «подключиться не удалось».
- `DSU_AUTOADB=0` через `dsu.conf` (проверен флаг `--no-autoadb`, файл — нет).
- Автовключение при канале `rish` как основном (Shizuku не запущен).
- Работа режима `dsu --restart-adb` при живой вкладке `dsu` (сессия оборвётся).

## 4. Отклонения от плана
1. В ожидании используется файл порта `adbfind` + `adb connect` с проверкой `get-state`, без поиска через `adb devices` (после включения отладки устройства ещё нет в списке).

## 5. Риски и находки вне плана
- **Телефон меняет сеть** (в файле порта встречались `192.168.0.3`, `192.168.0.233`, `10.14.238.211`), при смене сети Android сам выключает Беспроводную отладку — именно поэтому после перезапуска Termux она была выключена, и один раз `adb devices` показал только `offline`. Автовключение это покрывает; но каждый перезапуск отладки меняет порт.
- Один из прогонов дал «включил, но подключиться за 20 с не удалось»: в этот момент в файле порта был адрес другой сети (`192.168.0.233`), `adb connect` не прошёл; повторный запуск через минуту сработал. Это согласуется со сменой сети (не с ошибкой кода), но полностью не исключено. Если повторится — перепроверить.
- Любой процесс с разрешением `WRITE_SECURE_SETTINGS` (в том числе `am` Termux) может включать отладку через `dsu.ADB_WIFI` — по замыслу.
- Мод `dsuset` загружается только при старте Termux; после обновления мода нужен перезапуск.
