- Протокол (одно соединение — одна команда): `TOKEN\nrun ID\nBASE64(cwd)\nBASE64(argv, NUL-разделённый)\n` + сырой stdin до EOF; ответ — stdout+stderr слитно, закрытие соединения. Код возврата — **вторым соединением** `TOKEN\nstatus ID\n` → `N\n`.
- **Выбор реализации сервера**: `python3` (стоит на устройстве, 3.14.6; `socat`/`nc` из Termux не умеют аутентификацию). Выбор **способа возврата кода — второе соединение `status ID`**: поток stdout остаётся «сырым» (бинарно-безопасным, без разметки и без сентинелов, которые могли бы совпасть с выводом), на клиенте не нужно разбирать трейлер; ID (12 случайных байт) выдаёт клиент, результат хранится на сервере 300 с и выдаётся один раз.
- Ограничения сервера: слушает `127.0.0.1`, порт случайный; токен 32 байта (43 символа base64 без `/+=`), сравнение `hmac.compare_digest`; заголовок за 2 с, иначе закрытие; максимум 4 одновременных запуска; без `eval`/shell (`subprocess.Popen(argv)`); выход при смерти родителя (`getppid`, опрос раз в секунду) и по `SIGTERM`, с убийством дочерних процессов; журнал `$PREFIX/tmp/dsu-tx.log` (время, порт, первые 200 байт команды, код, отказы; токен не пишется).

## 3. Что не проверено и почему
- Работа `tx` через `rish` (канал shell от Shizuku) — Shizuku не запущен.
- Бинарный stdin/stdout больших объёмов, скорость передачи (проверялись только короткие данные).
- Повторное использование `ID` и очистка результатов по TTL (300 с) — по коду, не проверялось отдельно.
- Подбор токена/нагрузка (rate limit нет; токен 32 случайных байта).
- Поведение при `kill -9` на `dsu` вживую (сервер должен выйти по `getppid` ≤ 1 с; проверен случай нормального завершения и «родитель завершился» косвенно).
- `tx` в сессии без `--tx` (клиент на устройстве остался в `/data/local/tmp/dsu/bin/tx`, но без переменных печатает «нет DSU_TX_PORT/DSU_TX_TOKEN: запустите dsu --tx», код 125 — проверено только по тексту скрипта).

## 4. Отклонения от плана и найденные особенности
1. **`stdin` не может безусловно пересылаться через `cat`**: если у удалённого `tx` stdin — канал, который никогда не закрывается (так бывает в `adb shell` без tty, когда локальный stdin — терминал или висящий канал), пайплайн `{ заголовок; cat; } | nc` ждёт `cat`, даже когда сервер уже закрыл соединение (проверено: `nc` печатает вывод сразу, но весь пайплайн завершается только по EOF на stdin). Решение: **`tx` пересылает stdin только если он не терминал и не указан `-n`**; `dsu` в режиме команды выставляет `DSU_TX_NOSTDIN=1`, если локальный stdin — терминал. В интерактивной сессии (stdin — pty) обычный `tx cmd` не зависает; `echo hi | tx cat` работает; для скриптов с «вечно открытым» stdin — `tx -n`. 
2. Первая версия через `mkfifo` отвергнута: **SELinux запрещает shell создавать fifo в `/data/local/tmp/dsu/tmp`** (`mkfifo: Permission denied`). Фоновый `wait $!` в удалённом mksh ждёт весь пайплайн целиком — не помогает.
3. `toybox nc` **сам делает half-close** при EOF на stdin и ждёт закрытия сервером — флаги `-q`/`-W` не понадобились.
4. **Исправлена ошибка сервера**: пустой последний аргумент терялся (все хвостовые пустые элементы после разбиения по NUL удалялись). Теперь удаляется ровно один хвостовой терминатор; после исправления `[]` печатается.
5. Вывод слитый (stdout+stderr в один поток, без PTY); интерактивные программы (REPL, `vim`) через `tx` не работают.
6. Раскрытие `~`, `$VAR` и `*` выполняет **удалённая** оболочка до вызова `tx`: `tx ls ~` пытается открыть `/data/local/tmp/dsu/home` (Permission denied). Нужно `tx sh -c 'ls ~'` или кавычки `'~'`. Задокументировано в `CLAUDE.md`.
7. Байтовые литералы Python с кириллицей недопустимы — сообщения сервера кодируются через `encode()` (мелочь, исправлено).

## 5. Риски и находки вне плана
- Токен виден в командной строке удалённого процесса (`ps` другим процессом uid shell) — так требует спецификация (токен в удалённую строку). В файлы на устройстве токен не пишется. **Инцидент**: при отладке я случайно вывел в отчёт одной команды токен уже остановленной сессии (в тексте вывода `ps`); сессия закрыта, токен недействителен.
- `tx` исполняет в Termux произвольные команды любого, кто знает токен и достучится до порта; защита — токен (32 байта), только loopback, отключено по умолчанию, лимит 4, журнал.
- Клиент `/data/local/tmp/dsu/bin/tx` остаётся на устройстве после сессии (без переменных бесполезен).
- Моя прежняя проверка с `pkill -f` убила мою же оболочку (шаблон совпал с моей командной строкой) — урок: убивать по PID.
- Дефект `adbfind` по-прежнему вне плана.
